# ML Models

## Overview

| Model | Type | Library | Input | Output | Runs |
|-------|------|---------|-------|--------|------|
| Evasion Scorer | GradientBoostingClassifier | scikit-learn | Journey feature vector (8) | Probability 0–1 + top 3 features | Per journey update |
| Zone Anomaly Detector | IsolationForest | scikit-learn | Zone state vector (8) | Anomaly score + incident type | Every 30s per zone |
| Wildlife Detector | Rule-assisted threshold | Python + learned thresholds | Motion + ANPR gap + speed | Confidence 0–1 | Continuous (forest zones only) |
| Risk Zone Scorer | KMeans + composite | scikit-learn | Historical features per segment | Risk tier + dominant type | Nightly + on-demand |

**Universal rules**:
- All outputs include explanations
- All ML outputs require human officer confirmation before enforcement
- All models trained on simulator-generated labeled data
- All models stored as `.joblib` files in `ml_service/model_store/`

## Model 1: Evasion Scorer

**File**: `ml_service/models/evasion_scorer.py`

### Feature Vector (8 features)

| # | Feature | Computation | Type |
|---|---------|-------------|------|
| 1 | `journey_time_ratio` | Actual journey time / expected minimum for vehicle class and segment | float |
| 2 | `checkpoint_completeness` | Checkpoints hit / checkpoints expected on route | float 0–1 |
| 3 | `payment_detection_ratio` | FASTag events / ANPR events at Full Plazas | float 0–1 |
| 4 | `historical_evasion_count` | Past evasion flags for this plate (from `alert_feedback` where confirmed) | int |
| 5 | `time_of_day` | Hour of entry, sine/cosine encoded | float pair |
| 6 | `vehicle_class` | One-hot encoded (6 classes) | int vector |
| 7 | `entry_exit_pair` | Label encoded (CP-01→CP-12, CP-12→CP-01, partial routes) | int |
| 8 | `time_deviation_from_median` | (Journey time − median for same entry/exit pair today) / median | float |

### Training Data

- Generated by simulator: 85% normal journeys, 15% evasion journeys
- Evasion labels distributed across 3 types (no-FASTag, underpayment, plaza-skip)
- Minimum: 10,000 journey records
- Label: `is_evasion` (0 or 1)
- After initial deployment: augmented with confirmed/dismissed feedback labels

### Model Config

```python
from sklearn.ensemble import GradientBoostingClassifier

model = GradientBoostingClassifier(
    n_estimators=200,
    max_depth=5,
    learning_rate=0.1,
    subsample=0.8,
    min_samples_leaf=20,
    random_state=42
)
```

## Model 2: Zone Anomaly Detector

**File**: `ml_service/models/zone_anomaly.py`

### Input: Zone State Vector (8 features, every 30s)

See DATA_PIPELINE.md → Zone State Aggregator for full field definitions.

| # | Feature | Type |
|---|---------|------|
| 1 | `vehicle_throughput_deviation` | float |
| 2 | `flow_continuity_score` | float |
| 3 | `cctv_motion_mean` | float |
| 4 | `cctv_motion_rate_of_change` | float |
| 5 | `fastag_rate_deviation` | float |
| 6 | `upstream_vs_downstream_density` | float |
| 7 | `opposing_direction_flow_rate` | float |
| 8 | `time_slot_baseline_deviation` | float |

### Primary Model: Isolation Forest

```python
from sklearn.ensemble import IsolationForest

model = IsolationForest(
    n_estimators=150,
    contamination=0.05,
    max_samples='auto',
    random_state=42
)
```

Trained on normal zone state vectors (no incidents). Anomalies are vectors that deviate from normal patterns.

### Secondary Classifier: Incident Type

Triggered only when IsolationForest flags anomaly (score < threshold).

```python
from sklearn.ensemble import GradientBoostingClassifier

incident_classifier = GradientBoostingClassifier(
    n_estimators=100,
    max_depth=4,
    random_state=42
)
```

**Classes**: `stopped_traffic, slow_traffic, partial_blockage, full_blockage`

Trained on labeled incident signatures from simulator scenarios.

### Output Schema

```json
{
  "alert_id": "uuid",
  "zone_id": "ZONE-06",
  "km_range": "58–62",
  "anomaly_score": -0.82,
  "incident_type": "partial_blockage",
  "incident_confidence": 0.84,
  "detection_timestamp": "2024-01-15T09:30:30Z",
  "zone_state_snapshot": {"...current zone state vector"},
  "suggested_action": "Dispatch patrol to KM 58–62, possible partial blockage detected",
  "model_version": "anomaly_v2_2024-01-15"

```

### Baseline Management

- Per zone, per 15-minute time slot, per day type
- Rolling 30-day window
- Stored: Redis (cache, TTL 7d) + PostgreSQL (permanent)
- Baseline includes: mean, std, min, max for each zone state field
- Recomputed nightly by Risk Zone Scorer batch

## Model 3: Wildlife Detector

**File**: `ml_service/models/wildlife_detector.py`

**Active zones only**: ZONE-04 (KM 40–55, Cauvery buffer), ZONE-07 (KM 62–71, Mandya forest). Hardcoded in config, not ML-determined.

### Detection Pipeline (4 steps, sequential)

| Step | Signal | Check | Source |
|------|--------|-------|--------|
| 1 | ANPR gap | No vehicles in zone for ≥45 seconds | ANPR events |
| 2 | Motion pulse | Motion index 0.08–0.25 during gap | CCTV events |
| 3 | Speed reduction | Approaching vehicles show >15% longer inter-checkpoint time than baseline | Journey data |
| 4 | Scoring | Combine signals | Computed |

### Scoring

| Signals Present | Confidence | Action |
|-----------------|------------|--------|
| All 3 (gap + motion + speed) | 0.80–1.0 | Alert fired |
| 2 of 3 | 0.55–0.79 | Alert fired (medium priority) |
| 1 of 3 | 0.20–0.54 | Logged, no alert |

### Learned Thresholds

Motion pulse range (0.08–0.25) and speed reduction percentage (15%) are initial values. After deployment:
- Confirmed wildlife events → thresholds tightened (narrower motion range = more precise)
- Dismissed events → thresholds loosened
- Stored in Redis: `wildlife_thresholds:{zone_id}` with fallback defaults

### Output Schema

```json
{
  "alert_id": "uuid",
  "zone_id": "ZONE-04",
  "km_range": "40–55",
  "confidence": 0.85,
  "signals": {
    "anpr_gap_seconds": 62,
    "motion_pulse_value": 0.14,
    "speed_reduction_percent": 22
  },
  "detection_timestamp": "2024-01-15T21:15:00Z",
  "suggested_actions": [
    "Alert highway patrol",
    "Forest Authority Alert: Notify Forest Department (Cauvery Wildlife Sanctuary)",
    "Activate approaching vehicle warnings"
  ],
  "model_version": "wildlife_v1"
}
```

### Long-term Corridor Risk

Zones with 3+ confirmed wildlife events in 30 days → `corridor_risk_elevated = true` in `zone_risk_profiles`. Permanently elevated until manually reset.

## Model 4: Risk Zone Scorer

**File**: `ml_service/models/risk_scorer.py`

**Schedule**: Nightly batch (default 2:00 AM) + on-demand via API endpoint.

### Feature Extraction (per segment per time slot)

| # | Feature | Source |
|---|---------|--------|
| 1 | `incident_frequency_30d` | `historical_incidents` + recent `ml_alerts` confirmed |
| 2 | `severity_weighted_score` | Sum of (minor=1, major=3, fatal=10) per incident |
| 3 | `evasion_case_density` | Confirmed evasion cases per km in segment |
| 4 | `wildlife_flag_count` | Confirmed wildlife events in segment |
| 5 | `avg_response_time` | Mean `response_time_minutes` for past incidents |
| 6 | `heavy_vehicle_ratio` | Truck+Bus+MAV / total vehicles in segment |
| 7 | `time_of_day_risk_curve` | Hourly incident rate normalized to [0,1] |

### Pipeline

**Step 1**: Extract features for all 11 zones × 24 hourly slots = 264 feature vectors.

**Step 2**: KMeans clustering (k=4):
```python
from sklearn.cluster import KMeans

kmeans = KMeans(n_clusters=4, random_state=42, n_init=10)
```

Cluster mapping (post-fit, assigned by centroid severity):

| Cluster | Risk Tier | Color |
|---------|-----------|-------|
| Lowest centroid | Low | Green |
| Second | Moderate | Yellow |
| Third | High | Orange |
| Highest | Critical | Red |

**Step 3**: Dominant risk type per segment — whichever feature has highest z-score above mean. Categories: `incident_history, evasion_concentration, wildlife, combination`.

**Step 4**: Time-window risk curves — 24-hour array per segment identifying peak risk hours.

### Output (written to `zone_risk_profiles`)

```json
{
  "zone_id": "ZONE-06",
  "risk_tier": "High",
  "dominant_risk_type": "evasion_concentration",
  "risk_score": 0.78,
  "peak_risk_hours": [7, 8, 9, 17, 18, 19],
  "time_risk_curve": [0.2, 0.15, 0.1, ...24 values],
  "computed_at": "2024-01-15T02:00:00Z",
  "model_version": "risk_v1_2024-01-15"
}
```

## Training & Retraining

### Initial Training (before first run)

```bash
# Script: scripts/train_models.py
# 1. Runs simulator in fast mode to generate 10,000+ labeled journeys
# 2. Trains Evasion Scorer on labeled journey data
# 3. Trains Zone Anomaly Detector on normal zone state vectors
# 4. Trains Incident Type Classifier on labeled incident signatures
# 5. Initializes Wildlife Detector thresholds from defaults
# 6. Runs Risk Zone Scorer on seeded historical data
# 7. Saves all models to ml_service/model_store/
# 8. Writes initial model_metrics to PostgreSQL
```

### Nightly Retrain Cycle

1. Feedback Service accumulates confirmed/dismissed labels throughout the day
2. At 2:00 AM (configurable), ML Service triggers retrain
3. Steps:
   - Load current training dataset from PostgreSQL
   - Append new feedback-labeled examples
   - Retrain Evasion Scorer (full retrain, not incremental)
   - Retrain Zone Anomaly Detector with updated baseline data
   - Update Wildlife Detector thresholds from confirmed events
   - Run Risk Zone Scorer batch
   - Evaluate all models on holdout set
   - Save new model artifacts with version timestamp
   - Write metrics to `model_metrics` table
   - Hot-reload models in running ML Service

### Evaluation Metrics

| Model | Primary Metric | Secondary | Target |
|-------|---------------|-----------|--------|
| Evasion Scorer | Precision @ 0.7 threshold | Recall, F1, AUC-ROC | Precision > 0.85 |
| Zone Anomaly | False positive rate | Detection latency (seconds to flag) | FPR < 10% |
| Incident Classifier | Accuracy | Per-class F1 | Accuracy > 0.80 |
| Wildlife Detector | Recall (don't miss real events) | Precision | Recall > 0.90 |
| Risk Zone Scorer | Silhouette score | Cluster stability across runs | Silhouette > 0.4 |

## Reinforcement Feedback Loop

### Feedback Actions (per ML alert)

| Action | Effect on Training | Effect on System |
|--------|-------------------|------------------|
| Confirm | Journey features → positive example | Case count incremented |
| Dismiss — Sensor Error | Event excluded from training | `sensor_reliability:{cp}` decremented by 0.02 |
| Dismiss — Legitimate Exception | Features → negative example with exception context | Exception pattern logged |
| Dismiss — Insufficient Evidence | Threshold adjustment signal | Calibration review queued |
| Confirm incident | Zone baseline recalibrated, anomaly signature strengthened | Zone risk updated |
| Dismiss incident | Zone sensitivity adjusted, false positive pattern logged | Zone threshold loosened |
| Confirm wildlife | Corridor risk permanently strengthened | `corridor_risk_elevated = true` if 3+ in 30d |

### Visible Metrics (Authority Dashboard → Analytics tab)

- Model accuracy trend: 7-day rolling chart per model
- False positive rate: per alert type, 7-day rolling
- Confirmed case rate: per alert type, 7-day rolling
- Sensor reliability scores: per checkpoint, bar chart

### Hard Logic Immutability

**No feedback loop, no training cycle, no officer action, no model update ever touches the hard logic layer.** Hard logic rules are code constants. They produce legal event records that are never modified by any ML process.
